An agent skill for academic research, powered by [Agent Bayes](https://agentbayes.com). Run it inside an agent harness: Claude Code, Codex, or any harness that supports skills and MCP.

Ask it something small, such as what the field says about a question, whether a claim is supported, or a review of your paper, and it does that. Hand it a seed idea and it carries the whole effort: it builds the corpus, studies the literature, positions the claim, plans and runs the analyses, and writes, reviews, and typesets a paper that answers your question. It is one skill, `research`, that reads what you ask and how involved you want to be, and works at that scale.

## Usage Examples

Some common requests you can try:

- Can you review my paper?
- What does this library cover, and where is it thin?
- Can you help me draft a literature review?
- Can you reanalyze the radiocarbon samples from this study?
- Can you map the gaps and tensions in this corpus?
- Can you help me test this hypothesis?
- Can you write an essay about X?
- Can you plan an analysis that could support or falsify X, and check that it has the power to?

For something more serious, elaborate as much as you need, for example:

```
/z4n4-automated-research:research I would like to create a research paper on the low vs. high chronology debate in the southern Levant, and on what recent carbon dating studies support.

I would also like to challenge this paper:

<reference omitted>

It appears that there is an outlier in the data, so I would like to test their samples using the same software and calibration curve, and see what agreement values we get. I do not see their models published with model agreement values.

Moreover, the validity of dealing with cross-site samples also raises some doubt. Even if the samples are good, which I am not sure about, dealing with two sites creates an average. However, the question of the south vs. north is more concerned with when the transition started. This should be stressed, it is a process and we need to focus on the possible overlap.

Additionally, the claim about the difference between the south and north of the southern Levant may need to be revisited in light of the results.

Remain respectful, but challenge the paper carefully if you find any discrepancies.

Let’s start with an initial literature review.

I want to guide your work step by step throughout.
```

The shared discipline: **every factual claim about the literature is generated by Agent Bayes with page-level citations**, and every citation key is resolved and checked against the source text before it reaches you. The agent never invents a literature claim. When it believes something is true, it asks Agent Bayes to confirm, refute, or qualify it against the indexed corpus, which can grow to hundreds of sources, depending on the research.

## What it does

| You ask for…                               | You get                                                                                                                                                                       |
| ------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **papers and a corpus**                    | An Agent Bayes library of screened, legally acquired papers with authoritative metadata, and a sources × aspects coverage table scored 0–3 in half steps (●●◐ = 2.5)          |
| **what the literature says**               | A cited prose synthesis, with a positions table where positions differ: a review of a topic and its debates, a studied answer to one question, or the gaps a field leaves open and the questions they raise |
| **positioning and study design**           | Your idea placed against the literature, the question sharpened or reshaped when the literature calls for it, decision rules fixed in advance, and a simulation check that the design can detect what matters |
| **analyses**                               | Resumable, scripted experiments, reanalyses, and tests against the literature, reported honestly with intervals, and every reportable number exported for the paper              |
| **writing**                                | An argued outline within a length budget, then continuous prose in the field's register, learned from the field's own papers                                                   |
| **a review**                               | An audit of citations, numbers, and method, and an independent judge who asks whether the paper answers its question at its venue's standard, for at most two cycles             |
| **a paper from a seed**                    | All of the above in a sensible order, kept on one question, and a typeset PDF                                                                                                   |

Work that spans sessions lives in a project folder in your repository, `.z4n4/automated-research/{slug}/`. `QUESTION.md` holds the question, the venue, the budgets, and how involved you want to be. `LOG.md` records what was done, the decisions and their reasons, and the next step, so work resumes exactly where it stopped. Everything else is plain Markdown and scripts you can read and edit. When you change something, the agent works out what depends on it and updates only that.

## Working together

Say in your own words how involved you want to be, and change your mind whenever you like.

- **"I want to guide this step by step":** it does one meaningful piece at a time, shows you what it found and what it proposes next, and waits.
- **"Run with it":** it works through, decides the small things itself with its reasons logged, and reports at milestones with the work itself: the review, the plan, the results, the draft, the PDF.
- **Say nothing:** small tasks just get done. On a larger effort it checks in where the direction is set (the question, the claim, the outline) and before significant spending.

Some decisions stay yours however you work: spending beyond what you agreed to, changing a question or claim you settled, results that overturn what the work set out to show, anything only you can do (logging in for a paywalled paper, supplying a PDF), and whether the work is done.

Some practices make the results much better:

- **Work in your own field**, so you can judge the results. Citations are verified mechanically, but only you can judge whether the framing holds up to a domain expert.
- **Bring or approve the literature.** Point at an existing Agent Bayes library, or ask to see the papers before they are indexed.
- **Edit freely.** Edit any source file (`QUESTION.md`, the paper's sections, `corpus/coverage.json`, a review), and your edits are respected and carried through. `paper.md`, the LaTeX, and the coverage table in `CORPUS.md` are regenerated from them.

## Why Agent Bayes

The skill is only as good as the literature it reads, and Agent Bayes does the reading:

- **Clean passages from messy PDFs, at low cost.** Each page is read with vision OCR, and the layout is repaired: running headers, footers, and reference lists are dropped, and paragraphs broken across pages or around figures are rejoined. The text is split into semantically cohesive passages, and short bullets extracted from each passage are embedded with it. Search returns little noise and misses little, and every hit resolves to the original passage. Indexing costs about 0.35 credits per page.
- **A research agent built for scientific writing.** A multi-agent pipeline (plan, research, edit, replan) tuned for epistemic fidelity. It states each claim at the strength its source supports, keeps what a paper shows apart from what it only reports others showing, and attributes every claim to the passage it came from.
- **Figures and tables are searchable.** Each figure gets a generated visual description that is indexed and cited like text.
- **Citations point to the printed page.** Every passage carries both the PDF page and the printed page number, so a citation matches the page a reader sees.
- **Metadata from authoritative sources.** Titles, authors, and venues are looked up by DOI or arXiv id, then in Crossref, OpenAlex, and Semantic Scholar, before a model is asked to guess.
- **Search across languages.** Bullets are indexed in English while the cited passage stays in its original language, so English queries find papers written in other languages.

## Dependencies

### Agent Bayes (required)

[Agent Bayes](https://agentbayes.com) is a multi-agent research system built around libraries of indexed academic papers. The skill uses it to **explore the literature, test ideas, and synthesize citation-backed arguments and claims that are very accurate**. Every claim carries page-level citation keys that the skill resolves and verifies against the source text.

You need an Agent Bayes account and API key. The plugin bundles the MCP server configuration, so set your key in the environment:

```sh
export AGENT_BAYES_API_KEY="sk-..."
```

**Credits.** Indexing, research, and synthesis consume Agent Bayes credits:

- **Indexing costs around 0.35 credits per page** of source material, and it is usually the largest cost. While a batch indexes, 0.5 credits per page are held in reserve and then settled to the actual charge, so your balance needs to cover the reserve. The skill reads the live rates from Agent Bayes and estimates the cost from page counts before indexing anything.
- Exploring and reviewing an indexed corpus mostly uses search, at 0.05 credits per call of up to 10 queries, plus a few library chat questions.
- A full research paper of **15–30 written pages with ~40 references** needs around **500 credits**: about 300 to index a corpus of 40–60 papers (roughly 900 pages), and the rest for library chat during research and synthesis. The **Pro subscription** (2700 credits/month) is recommended if you write papers regularly or index large corpora.
- A **2000–3000 word essay with 10–15 sources** will most probably fit in the **Starter subscription**.
- Top-ups are available if you run over.
- **Index once, reuse often.** Several projects and papers can share one library, and the skill checks your libraries before building a new one.

### Optional

- **LaTeX toolchain** (`xelatex`) for a compiled PDF. Without it, the deliverable is a fully cited Markdown paper.
- **Perplexity.** When the Perplexity MCP is connected, the skill uses it for broad literature sweeps, and as a web-grounded second reader alongside the review judge. Without it, discovery uses free scholarly APIs (arXiv, OpenAlex, Semantic Scholar) and web search.

## Installation

### Claude Code (plugin)

```
/plugin marketplace add loudinthecloud/z4n4-automated-research-skills
/plugin install z4n4-automated-research@z4n4-automated-research-skills
```

Make sure `AGENT_BAYES_API_KEY` is set in your environment before starting Claude Code. The skill is then available as `/z4n4-automated-research:research`, and the agent also picks it up on its own when you ask a research question.

### Codex

```sh
git clone https://github.com/loudinthecloud/z4n4-automated-research-skills.git
mkdir -p ~/.codex/skills
cp -R z4n4-automated-research-skills/plugins/z4n4-automated-research/skills/research ~/.codex/skills/
```

Then configure the Agent Bayes MCP server in `~/.codex/config.toml`:

```toml
[mcp_servers.agent-bayes]
command = "npx"
args = ["-y", "mcp-remote", "https://api.agentbayes.com/mcp/", "--header", "X-API-Key:YOUR_AGENT_BAYES_API_KEY"]
```

### Manual (any harness with skill support)

Copy `plugins/z4n4-automated-research/skills/research/` into wherever your harness discovers skills (for example `~/.claude/skills/`), and configure the Agent Bayes MCP server as above.

## Development

```sh
make install                                   # install the plugin from this checkout
make refresh                                   # reinstall after local edits, then run /reload-plugins
make test                                      # script tests
python3 -m unittest discover tests             # coverage matrix, paper assembly, LaTeX build
RUN_LATEX=1 python3 -m unittest discover tests # also compiles a PDF (needs xelatex)
```
